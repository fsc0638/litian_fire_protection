# 部署與自動部署

主機以 GitHub clone 部署；推上 main 後自動測試、通過才部署。腳本說明另見 `deploy/oracle/README.md`。

← 回到 [專案介紹](../README.md)

## 部署

主機上以 GitHub clone 部署（2026-10-01 起）：

```
# 第一次
git clone https://github.com/fsc0638/litian_fire_protection.git /opt/litian/repo
# 手動更新（備份資料庫 → git pull → 同步部署檔 → 重建 api → 重載法規庫 → 健康檢查）
bash /opt/litian/repo/deploy/oracle/06_update_from_git.sh
# 啟用自動部署（只需一次）
bash /opt/litian/repo/deploy/oracle/11_install_autodeploy.sh
```

**自動部署**（2026-10-05 起）：推上 GitHub `main` 後約 2～3 分鐘內，主機自己發現新提交 → 在拋棄式容器裡用新版程式跑全部測試（含資料庫整合測試；測試用專屬的資料庫帳號，碰不到正式資料）→ 通過才部署那一個提交（部署前自動備份資料庫）。主機上的指令一律不要加 `sudo`。

- 測試沒過：不部署，網站維持原版本；修好後再推一次就會重試。測試環境本身出錯（不是測試沒過）會自動重試，連續 3 次才暫停。
- 部署後健康檢查不過（含背景服務一直重啟），或部署途中被中斷（逾時、重開機）：程式與映像自動換回前一版，並**暫停自動部署**；處理後執行 `bash /opt/litian/repo/deploy/oracle/10_autodeploy.sh resume`，會重新測試並部署。注意：換回的是程式與映像，資料庫結構變更不會自動還原（需要時用 `/opt/litian/backup/` 裡部署前的備份）。
- 健康檢查通過、只有後續的法規庫重載失敗：保留新版，紀錄裡會有警告，手動重跑即可。
- 看狀態與最近紀錄：`bash /opt/litian/repo/deploy/oracle/10_autodeploy.sh status`；要手動維護時先 `pause`。紀錄在主機 `/opt/litian/autodeploy/`。目前沒有推播通知，暫停時只看得到狀態。
- `main` 的歷史被改寫（強制推送）時會暫停。處理方式：`git -C /opt/litian/repo fetch origin && git -C /opt/litian/repo reset --hard "$(git -C /opt/litian/repo merge-base HEAD origin/main)"` 再 `resume`（新的 main 會先測試再部署；不要直接 reset 到 origin/main 再手動部署，那樣會跳過測試）。
- 磁碟剩不到 6 GB 時整輪略過，清出空間後自動繼續；舊映像用 ID 清除，不使用 `docker system/builder prune`（同主機有其他服務）。
- 做法是主機定時讀取公開 repo，不需要金鑰或 webhook，GitHub 端不用設定。**能推上 `main` 就等於能在主機上以可 sudo 的身分執行程式**（新版的部署腳本會在主機執行；同主機的其他服務與 `.env` 金鑰都在範圍內），所以 `main` 的分支保護必須維持：只能經負責人核准的 PR 合併、禁止強制推送。

## 轉檔器升級後：全部重新處理

轉檔器（LibreDWG）修正或升級後，舊的轉檔結果可能夾帶錯誤內容（例：0.14 套上游修正 #1416 之前，含換行的文字後面會接上亂碼）。

開始前：

- 建議暫停自動部署：`bash /opt/litian/repo/deploy/oracle/10_autodeploy.sh pause`，全部跑完再 `bash /opt/litian/repo/deploy/oracle/10_autodeploy.sh resume`。部署會重啟 worker，處理到一半的大檔要從頭來。
- 從工作台匯出各案件的報告留存。審核決定是照缺失的識別碼（規則、樓層、房名、位置或設備名、標註文字）對應的：房名、標註文字原本夾帶亂碼的缺失，重跑後識別碼會變、回到未審核（舊的決定還在資料庫，只是對不上），要請審核人員重看。
- 等 worker 閒著再執行（沒有排隊、處理中、畫原圖中，查法見下面「看進度」）：worker 正在處理這些案件的檔時 reprocess 不會動；畫原圖和抽取大檔同時跑也可能記憶體不足，失敗的檔不會自動重試。
- 確認磁碟空間：舊的轉檔結果不刪，移到各案件資料夾的 `.pre-reprocess/<執行時間>/`，重跑又會產生差不多大的新檔。試跑的「合計」那行列出舊轉檔結果的總大小，`df -h /opt/litian` 的剩餘空間要比它多（自動部署另外要留 6 GB）。

新版部署好後在主機上執行：

```
cd /opt/litian
sudo docker compose exec -T worker python -m litian.drawing.cli reprocess --all --dry-run   # 先看會做什麼，不動任何東西
sudo docker compose exec -T worker python -m litian.drawing.cli reprocess --all             # 或 --case 案件ID（可重複）
```

- 每個 DWG／DXF 都完整重跑：DWG 重新轉檔、重新綁定外部參考、重新抽取、重新檢核，有樓層圖的重畫 CAD 原樣圖。移走的只有 worker 產生的 `.converted.dxf`、`.bound.dxf`：不刪，移到 `data/cases/<案件ID>/.pre-reprocess/<執行時間>/`（報告逐案列出，worker 不會用到），上傳的原檔不動；舊結果在工作台照常顯示，重跑到該檔時才更新。
- worker 正在處理這些案件的檔（處理中、檢核中）時，整個不動，印出「worker 正在處理：…，沒有任何更動，等它處理完再執行一次」、結束碼 1：等它處理完（`… cli status 案件ID` 看狀態）再執行同一個指令。試跑也會列出這些檔（「worker 正在處理，正式執行會停下」）。
- 有轉檔結果移不走（權限不足等）時，會在移任何檔之前停下；試跑也會列出來。
- 上傳的原檔不見了的檔不動（轉檔結果是僅存的圖），上次把它綁成外部參考的主圖也不動（重跑會綁不到）；報告列在「略過」。
- 看進度：`sudo docker compose exec -T postgres psql -U litian -d litian -c "SELECT status, count(*) FROM case_file GROUP BY 1" -c "SELECT cad_state, count(*) FROM case_file WHERE cad_state IN ('pending', 'rendering') GROUP BY 1"`。沒有 queued、processing、reviewing，也沒有 pending、rendering，就是全部完成。單一案件用 `… cli status 案件ID`。worker 一次處理一個檔，排隊的檔都處理完才開始畫原圖，整批可能要一兩個小時以上。failed 的檔看 error 欄，不會自動重試。
- 執行一次就好（中途中斷或出錯才再執行）：再執行會把已經重跑完的檔又排一次（轉檔結果再移一份到新的 `.pre-reprocess/<執行時間>/`）。

新版轉不了某個 DWG（`… cli status 案件ID` 顯示 failed，錯誤是轉檔失敗或等待轉檔逾時）時，可以把舊的轉檔結果搬回來用（內容是舊版轉的，帶著舊的錯誤）：

```
cd /opt/litian
# 1. 搬回原處（有 存檔名主體.bound.dxf 也一起搬）。存檔名＝案件資料夾裡的檔名，例 001_Area_1F.dwg；主體＝001_Area_1F
sudo mv data/cases/案件ID/.pre-reprocess/執行時間/存檔名主體.converted.dxf data/cases/案件ID/
# 2. 它是別的圖的外部參考時：先重跑的主圖綁不到它（記「存檔名（尚未轉檔）」），把這些主圖排回完整重跑
sudo docker compose exec -T postgres psql -U litian -d litian -c "UPDATE case_file SET status = 'queued', review_only = false, attempts = 0 WHERE case_id = 案件ID AND status IN ('done', 'failed') AND stats->'xref'->'failed' ? '存檔名（尚未轉檔）'"
```

- 這個檔自己維持 failed（綁定外部參考看到轉檔結果就直接用，不會再送轉檔）。第 2 步不要改用 reprocess：它會把搬回來的檔又移走。
- 全部完成、確認沒有要搬回來的檔之後，刪掉舊的轉檔結果釋放空間：`sudo rm -rf /opt/litian/data/cases/*/.pre-reprocess`。

對外：`https://<SITE_ADDRESS>/api/...`（sslip.io 測試網址常被企業網路攔截，正式期要換自己的網域）。
